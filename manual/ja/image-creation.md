# 画像の作成方法

この文書は、inku v1.85（Web Build 564）のWeb UIとCLIを使って作品を作る手順です。入力した記述は、解釈、決定的な中間展開、構造化、レンダリングの順に処理されます。

```text
記述 -> 正規化DDL -> 拡張DDL -> JSON Score -> SVG
```

記述は作品の楽譜、SVGはその一回の演奏です。同じ記述でも、モデル、配置seed、render seedにより異なる作品になり得ます。

## 1. ログインと画面表示

1. ブラウザでinkuのWeb UIを開きます。
2. `ユーザー名`と`パスワード`を入力します。
3. `ログイン`を押します。

左側のアプリレールから、設定、プロフィール、テーマ、UI表示言語、ログアウトを操作できます。UI表示言語と指示文の言語は別です。日本語UIへ英語を書いた場合も、英語UIへ日本語を書いた場合も、通常生成では入力内容から指示文言語を自動判定します。判定材料がない入力だけUI表示言語を既定値にします。

## 2. 最初の一枚を生成する

1. `記述`タブを開きます。
2. `指示`欄へ短い文章を入力します。
3. 必要に応じて`色カタログ`、`モデル選択`、`キャンバス`を設定します。
4. `生成する`を押します。
5. 右側の`描画`タブへ作品が表示され、通常履歴へ保存されることを確認します。

最初の一枚は本歌です。推敲用の「言葉でタッチを変える」は初回生成には適用されません。

例:

```text
山の向こうに月が昇る
```

```text
青いクレヨンの線がゆっくり波打つ
```

```text
白い余白に、赤い小さな円を右上へ三つ置く
```

## 3. 記述を書く

安定した結果を求める場合は、観察できる物理的な指示を一文ずつ書きます。

```text
色 + 大きさ + かたち + 数 + 場所 + 動き
```

例:

```text
背景を白で埋める。
青い細い線を左下から右上へ三本引く。
赤い小さな円を右上に三個置く。
```

| 種類 | 例 |
|---|---|
| かたち | 円、楕円、三角、四角、線、弧 |
| 色 | 白、黒、青、赤、緑、灰 |
| 場所 | 上、下、中央、左端、右端、上端、下端、隅 |
| 動き | 置く、並べる、埋める、散らす、引く、敷き詰める |
| てざわり | 鉛筆、ペン、ロットリング、クレヨン、チョーク、細筆、太筆、ビュラン、ドライポイント |
| つらなり | 実線、破線、点線、一点鎖線 |
| ゆらぎ | 細かく、大きく、ゆっくり、速く、揺れる、波打つ、震える、滲む |

## 4. 歳時記を参照する

`歳時記`はinkuの語彙辞書です。

1. 最初の生成後、`解釈（正規化DDL）`行の`歳時記`を押します。
2. 語彙へポインターを置き、描画への作用例を確認します。
3. 語彙を選び、DDLのカーソル位置へ挿入します。

歳時記は自動補完ではありません。必要なときだけ参照し、記述を既存語彙へ自動的に狭めません。

## 5. 解釈とコードを確認する

生成後、左側の`解釈（正規化DDL）`に、Stage 1が入力をどう読んだかが表示されます。

- 記述: 人間が書いた言葉
- 正規化DDL: コア語彙へ整理された描画指示
- JSON Score: Stage 2が作る機械可読な楽譜
- 描画: Rendererが作るSVG

`DDL編集`でコードを拡大編集し、`自動補正`で不可視色、過密、契約違反などの決定的な補修を有効または無効にできます。編集したDDLから描く場合は`コードから描画`を押します。

## 6. 色カタログ、モデル、キャンバスを選ぶ

記述タブ上部の操作は次の生成に使われます。

| 操作 | 内容 |
|---|---|
| 色カタログ | `赤`、`青`、`灰`などの抽象色名を実色へ対応付けるカタログを選ぶ |
| モデル選択 | Stage 1（解釈）とStage 2（描画）の推論モデルを選ぶ |
| キャンバス | Square、Golden、A4、Wide、Vertical、Byobuなどの縦横比を選ぶ |

キャンバスが変わっても座標は0.0〜1.0に正規化されます。表示中作品の実設定と、次の生成に使う設定は別です。Canvas上部の`表示中`と、下部の`次の描画`を見分けてください。

## 7. 推敲する

右側の`推敲`タブには、`調整`、`モデル比較`、`言語比較`があります。推敲対象を切り替えると、その作品に属する未保存候補は破棄されます。サブタブを切り替えるだけでは候補を保持します。

### 7.1 調整

一度に変更する要素を一種類だけ選びます。

| 推敲要素 | 変わる範囲 |
|---|---|
| 配置を変える | 読み取りを保ち、Stage 2で座標、サイズ、配置バランスを再構成する |
| 読み取りを変える | Stage 1から読み直し、正規化DDL、配置、タッチを再生成する |
| 色カタログを変える | DDL、JSON Score、配置、タッチを保ち、色カタログだけを変える |
| 言葉でタッチを変える | 入力語からRendererのperformance seedだけを決め、線質、太さの揺らぎ、滲みを変える |

通常の調整では`1案を作る`または`4案を作る`を選べます。「言葉でタッチを変える」は同じ言葉が同じタッチ（Seed）になる決定的操作なので、1案だけ生成できます。語句は作品の意味、読み取り、DDL、JSON Score、配置には作用しません。

候補は未保存です。候補右上の選択操作で採用対象を選び、履歴へ保存してください。保存とスターは別の操作です。

### 7.2 モデル比較

同じ記述を別のStage 1／Stage 2モデル構成で生成し、作品と正規化DDLを比較します。

- `Stage 1/2共通`
- `Stage 1固定 + Stage 2比較`
- `Stage 1比較 + Stage 2固定`

比較対象と同じモデル構成は除外されます。比較結果は自動保存されません。`+`で採用するか、スター操作でスター付き履歴として保存します。

### 7.3 言語比較

通常生成の自動判定を変更せず、比較実行時だけStageごとの日本語／英語を明示します。比較モードはモデル比較と同じ三種類です。結果にはStage 1／2の実使用言語と正規化DDLが表示され、採用時は`language_variation`として系譜へ記録されます。

## 8. 生成情報を確認する

Canvas下部の`生成情報`を開くと、選択中作品の記録を確認できます。

| タブ | 主な内容 |
|---|---|
| 詳細 | Stage 1／2モデル、Stage 1／2言語、色カタログ、キャンバス、各seed、hash、render engine、Build、処理時間、token数 |
| プロンプト | Stage 1／2のsystem promptとuser prompt |
| JSON | 詳細情報の機械可読なトップレベル項目とJSON Score |

JSONには`stage1_instruction_lang`、`stage2_instruction_lang`、`render_seed`、`composition_seed`、`interpretation_seed`、`description_hash`、`derivation_kind`、`derivation_metadata`などが含まれます。JSON Score本体と生成情報を混同しないでください。

## 9. 系譜をたどる

`系譜`タブは、作品がどの明示操作から派生したかを表示します。タッチ、配置、読み取り、モデル、言語、DDL編集、記述編集、再描画、キャンバス変更などが親子関係として記録されます。

- 見た目の近さ、同じ記述、時刻だけから親子関係を推測しません。
- 未保存候補からさらに制作を続ける場合、直接の候補だけを`中間作品・履歴非表示`として系譜へ保存します。
- `新しい起点にする`で、次の制作を独立したrootとして始められます。
- 系譜カードから通常履歴への昇格、コメント、スター、ゴミ箱操作ができます。

## 10. 履歴を管理する

下部履歴ストリップは時系列での高速な前後移動に使います。`履歴管理`では、`時系列`と`系譜ごと`を切り替えられます。

- 検索、スターのみ、通常履歴／ゴミ箱の絞り込み
- サムネイル／リスト表示
- 個別または複数選択によるゴミ箱移動と復元
- 系譜単位の展開と一括選択
- 表示中作品への同期と最初／最新ページへの移動

`系譜ごと`は保存済みlineage node／edgeだけを根拠にグループ化します。`lineage_only`の中間作品とtombstoneは通常履歴件数へ含めません。

Canvasの`近い作品`は構図特徴が近い履歴を最大3件まで、順位や数値評価なしで示す鏡です。近さは系譜ではなく、生成や品質判定にも使われません。

## 11. 画像を書き出す

Canvas下部の`SVG`または`PNG`から保存します。

| 形式 | 用途 |
|---|---|
| SVG Display | Web表示とPNG生成の元データ |
| SVG Editable | IllustratorやAffinityで編集しやすい構造 |
| SVG Compat | 汎用的な受け渡しを優先 |
| PNG | 指定解像度のラスター画像 |

## 12. バッチ生成

1. `バッチ`タブを開きます。
2. 一行に一つの記述を入力します。
3. 必要なら描画ごとの色カタログランダム選択を有効にします。
4. `生成する`を押します。

処理中は現在行、進捗、経過時間、token数、現在の解釈を表示します。失敗行はレポートから確認でき、成功した作品は履歴へ保存されます。

## 13. デモ

`デモ`タブは、シードフレーズから短い指示文を生成し、その記述で描画を繰り返します。DB保存、artifact保存、指示文生成モデル、表示間隔、色カタログランダム選択を設定できます。自動保存を無効にした場合でも、気に入った現在作品を明示的に履歴へ保存できます。

## 14. CLIから生成する

CLIはWeb UIと同じHTTP APIを使います。

```sh
cd cli
uv run inku-cli --base-url http://127.0.0.1:8100 login -u admin
uv run inku-cli --base-url http://127.0.0.1:8100 paint "青い線が左下から右上へゆっくり波打つ" -o out --png --save-history
```

```sh
uv run inku-cli --base-url http://127.0.0.1:8100 batch -f prompts.txt -o out --png --continue-on-error
uv run inku-cli --base-url http://127.0.0.1:8100 history --limit 20
```

## 15. うまく描けないとき

| 症状 | 対処 |
|---|---|
| 意図と違う | 正規化DDLを確認し、場所、数、形、素材を具体化する |
| 画像が単調 | てざわり、ゆらぎ、配置、色を一つだけ足す |
| 要素が多すぎる | `三本`、`十二個`のように数を明示する |
| 生成が遅い | providerの待ち行列を待つか、モデル選択で軽いモデルへ変える |
| エラーになる | 記述を短くし、一文一指示へ分ける |
| 比較結果が残らない | 比較候補の`+`またはスターで履歴へ採用する |
| 推敲候補が消えた | 推敲対象を変更すると未保存候補が破棄されるため、先に保存する |

感情的な評価語だけでなく、観察できる物理語を書きます。

```text
黒い太筆の線を中央に一本置く。
灰の円を周囲に七個、少しばらつかせて並べる。
```
