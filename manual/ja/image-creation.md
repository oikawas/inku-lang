# 画像の作成方法

この文書のWeb操作はinku v2.15.15（Build 1091）に対応します。入力した記述は、写生、解釈、決定的な拡張、構造化、演奏の順に処理されます。

```text
記述 -> 写生（Stage 0.5） -> 解釈（Stage 1） -> 指示書（正規化DDL）
     -> プラグイン展開 -> 確定（Stage 1.5） -> JSON Score（Stage 2） -> SVG
```

記述は作品の楽譜、SVGはその一回の演奏です。同じ記述でも、モデル、写生、配置seed、render seedにより異なる作品になり得ます。

UIで使う語は次のとおりです。

| 語 | 対応 |
|---|---|
| 記述 | 作者が書く詩歌的な入力。作品の最上層 |
| 写生 | 記述を物の言葉へ写した自然文にするStage 0.5の行為 |
| 解釈 | 記述（または写生文）を指示書へ読み解くStage 1の行為 |
| 指示書（正規化DDL） | 解釈が生む実行仕様 |
| 楽譜（JSON Score） | 指示書を構造化した中間表現。決定的に保存される |
| 演奏（SVG） | 楽譜を描く一回性の結果 |

## 1. ログインと画面表示

1. ブラウザでinkuのWeb UIを開きます。
2. `ユーザー名`と`パスワード`を入力します。
3. `ログイン`を押します。

左側のアプリレールから、設定、プロフィール、テーマ、UI表示言語、ツールチップの表示切替、ログアウトを操作できます。レールは伸ばす／格納するを切り替えられます。

UI表示言語と記述の言語は別です。日本語UIへ英語を書いた場合も、英語UIへ日本語を書いた場合も、通常生成では入力内容から記述の言語を自動判定します。判定材料がない入力だけUI表示言語を既定値にします。`記述の言語`で`自動`／`日本語`／`English`を明示することもできます。

`設定`の`表示と操作`にある`UIモード`で、画面に出す項目の量を選べます。

| UIモード | 内容 |
|---|---|
| シンプルUI | 必須項目と履歴を表示する |
| カスタムUI | 必須項目に、選んだ項目を追加する |
| フルUI | 利用できる項目をすべて表示する |

UIモードはレール左側のアイコンからも切り替えられます。**濃い横棒の本数がいまのモード**で、1本がシンプル、2本がカスタム、3本がフルです。メニューも同じ順（シンプル→カスタム→フル）で並びます。

ユーザーメニュー、設定、単発の記述と描画、キャンバスは常に表示されます。履歴・ライブラリは必要に応じて開きます。カスタムUIで追加できるのは、まとめ描き・デモ、モデル・色・写生・キャンバス設定、指示書の表示・編集、処理時間・トークン・生成情報、推敲・比較・書き出し・作品操作、履歴と作品の移動、テーマ・言語・作品情報の7群です。

本書はフルUIを前提に説明します。シンプルUIでは記載の操作の一部が画面に出ません。

### 自分のパスワードを変える

1. 左のアプリレールで自分のユーザー名を押し、`プロフィール`を選びます。
2. `現在のパスワード`と`新しいパスワード`の両方を入力します。**片方だけでは変わりません**（メールアドレスだけを直すときは2つとも空のままにします）。
3. `保存`を押します。

新しいパスワードは8文字以上です。**現在のパスワードが合っていないと変わりません。**

**⚠ 忘れてログインできなくなった場合、この画面には入れません。**戻り道はサーバー側の`inku-admin reset-password`だけで、`サーバー設定`の2.2に書いてあります。管理者は他の利用者のパスワードを`設定`の`ユーザー管理`から変えられます（そちらは現在のパスワードを要しません）。

## 2. 最初の一枚を描く

1. `記述`タブを開きます。
2. 入力欄へ短い文章を入力します。
3. `次に描く条件`で、必要に応じて`モデル`、`色カタログ`、`写生`、`暴れる`、`キャンバス`を設定します。
4. `描画する`を押します。
5. 右側の`作品`タブへ演奏が表示され、履歴へ保存されることを確認します。

待っているあいだ、`描画する`のそばの表示が、いま働いている層の名を出します（`写生中…`、`解釈中…`、`構造化中…`、`演奏中…`）。**表示は推測ではなく、各層が終わった時点でサーバーから届く合図で切り替わります**（v2.13.39）。`写生`を`切`にしている場合は`写生中…`から始まりません。

最初の一枚は本歌です。推敲の「言葉でタッチを変える」は初回生成には適用されません。

例:

```text
山の向こうに月が昇る
```

```text
青いクレヨンの線がゆるやかに波打つ
```

```text
白い余白に、赤い小さな円を右上へ三つ置く
```

入力欄の下の右に、記述の長さが出ます。記述が詩型・形式に近いときだけ、その名前も出ます。日本語は音数で数え、俳句/川柳（5-7-5）・片歌（5-7-7）・都々逸（7-7-7-5）・短歌（5-7-5-7-7）・旋頭歌（5-7-7-5-7-7）・仏足石歌（5-7-5-7-7-7）・長歌（5-7を3回以上重ねて7で結ぶ）に近ければ「音数 17/17（俳句/川柳）」のように出ます。俳句と川柳は音数では区別できないので、両方を示します。改行・空白・読点で句に分けて書くと、句の形で判定します。各句と合計がそれぞれ2音以内の違い（字余り・字足らず）なら、その詩型です。区切らずに書いたときは合計が2音以内の詩型になり、38音では旋頭歌と仏足石歌の両方を示します。どれにも近くなければ「音数 52」のように数だけが出ます。音数はServerが漢字の読みを辞書で引いて数えます。古語や詩の読み、辞書に無い語は、読み上げたときと違って数えることがあります。辞書が読めない字があると「約」が付きます。数え終わるまでの一瞬は文字数で出ます。英語は行数で数え、形式に近ければ「行数 3/3（ハイク）」のように出ます。1行は形式としません。2行はカプレット、3行は音節が17以下ならハイク、それより多ければターセット、4行はクワトレイン、5行は各行の音節が2-4-6-8-2に近ければシンクェイン、14・19・39行（それぞれ前後1行まで）はソネット・ヴィラネル・セスティーナです。音節はServerが発音辞書（CMUdict）で数えます。どれも目安であって上限ではありません。作品編集メニューの`記述を変える`にも同じ表示が出ます。管理者は、設定の`その他（サーバー）`で日本語と英語の判定をそれぞれ切れます。切った言語は、文字数または行数だけが出ます。

## 3. 記述を書く

安定した結果を求める場合は、観察できる物理的な指示を一文ずつ書きます。

```text
色 + 大きさ + かたち + 数 + 場所 + 動き
```

例:

```text
背景を白で埋める。
青い細い線を左下から右上へ三本引く。
赤い小さな円を右上に三個置く。
```

| 種類 | 例 |
|---|---|
| かたち | 円、楕円、三角、四角、線、弧 |
| 色 | 白、黒、青、赤、緑、灰、黄、橙、紫 |
| 場所 | 上、下、中心、左端、右端、上端、下端、隅 |
| 動き | 置く、並べる、埋める、散らす、引く、敷き詰める |
| てざわり | 鉛筆、ペン、ロットリング、クレヨン、チョーク、細筆、太筆、ビュラン、ドライポイント |
| つらなり | 実線、破線、点線、一点鎖線 |
| おもて | 空、塗り、刷き、粒、点描、平行線、交差線、アクアチント |
| さばき | 濃い、程よい、薄い |
| じ | 紙、和紙、薄墨地、木炭地、カンバス、画用紙、メゾチント |
| ゆらぎ | 細かく、大きく、ゆるやかに、小刻みに、揺れる、波打つ、にじみ |

記述に書かれていないものは、どの層も足しません。逆に、書かれたものは可能な範囲で描かれます。

**`地:`で紙を名指すと、痕の走り方が変わります**（v2.13.31）。七つの支持体はそれぞれ吸い方と歯の強さを持つので、同じ記述・同じ設定でも和紙とカンバスでは痕が違う形で出ます。効き方は道具によって大きく違い、ペンのように紙をほとんど拾わない道具ではほぼ見えません。**`面: 粒`とゆらぎの`にじみ`は、線や弧に付けてもそのまま残ります**（同じくv2.13.31。にじみは歳時記 v2 でおもてからゆらぎへ移りました）。この二語は内側の在り方ではなく痕の走り方を言うので、その一命令だけ紙を強く働かせます（強めるのは三倍までです）。**`面: 刷き`も、線や弧に付けてそのまま残ります**（v2.13.35。歳時記 v2 で`薄墨`を改めた語で、旧い`薄墨`は`薄い刷き`になります）。ただし刷きは紙の話ではなく筆の運び（幅の広い掃き）なので、紙を強く働かせるのではなく、**その一本を幅が三倍の帯として引きます**（濃さは道具の〇・八倍。淡くしたいときは、さばきの`薄い`を添えます）。**v2.13.35より前は、線や弧に付けた薄墨は一画素も描かれていませんでした。**残る面の語は、これまでどおり直前の閉じた図形へ移り、移せる先が無いときは落ちます。

書いた数は、「三本だけ」のように強めなくても、書いたとおりに描かれます。効くのは、その一文が指す群がひとつに決まるときです。同じかたち・同じ色・同じ太さの群が文中に複数あって、どれのことか決まらない場合は、数を動かしません。数が届く範囲は「[サーバー設定](server-configuration.md)」の`述べた数の扱い`が決める境目までで、既定では二百三十九までです。それ以上は群れとして見せます。強く求めた数が一枚の上限や一つの群の上限を越えるときは、途中まで描くのではなく、数を動かさずそのままにします。**数字の読み方は日本語と英語で同じです** —— 英語で書いた`12`も、隣にプラグイン語の漢字があっても個数として読みます。プラグインを名指す句が数を述べていないときは、その文から読みます（句にあればそちらが優先）。**方向・種類・度・行・列などを表す数と、小数は個数として読みません**（`四つの方向`の4、`30度`の30、`0.11`）。

書いた大きさも同じ扱いです。「小さな円」のように大きさを述べた文は、その大きさで描かれます。効くのは、その大きさを述べた句がひとつに決まるときで、同じかたちの句が複数あってどれのことか決まらない場合は、大きさを動かしません。`半径0.02`のように値そのものを書いた場合は、その値を使います。大きさを述べていない記述は、これまでどおり既定の大きさで描かれます。

行頭の通し番号と角括弧の注記は記述者のもので、描画の対象ではありません。番号と注記だけを書いて描くところが残っていない場合は、その旨のエラーになります。

## 4. 写生（Stage 0.5）

`写生`は、記述を物の言葉へ写した自然文に変えてから解釈へ渡す層です。記述タブの操作列にある`写生`から選びます。

| 選択 | 内容 |
|---|---|
| 細かく | 細かく区切って解釈する。一文に一つのことを書く（既定） |
| 大きく | 大きく区切って深く解釈する。関係のあることを一文に束ねる |
| 切 | 写生を通さず、記述をそのまま解釈へ渡す（推奨しない） |

細かくと大きくは、述べる量ではなく区切りの大きさを変えます。細かく区切ると指示の数が増え、大きく区切ると一つの指示が担う量が増えます。

写生文は記述の代わりに、解釈、プラグイン展開の発動判断、Stage 1.5の三つへ届きます。生成後は左側の`写生（Stage 0.5）`に結果が表示され、その場で直せます。直した写生文はそのまま解釈へ渡ります。

写生が返らなかった場合は記述をそのまま解釈へ渡し、その旨を作品に記録します。写生を通さなかった作品にも同じく記録が残ります。

`写生（Stage 0.5）`と指示書（`指示書（日本語DDL）`など）は、それぞれ見出しの三角で畳めます。畳んでも見出し、区切り、`編集`は残り、畳んだまま`編集`を押せば開きます。**開閉はブラウザではなくアカウントに保存されます** — 別の機械で開いても同じ状態です。初期値は写生が開、指示書が閉です。

## 5. 歳時記を参照する

`歳時記`はinkuの語彙辞書です。`指示書を新規作成`または`指示書を編集`を開くと、共通の指示書エディタの下に広い歳時記一覧が出ます。語彙を閉じれば本文を広げられます。

1. `指示書を新規作成`では空の本文から、`指示書を編集`では表示中作品の本文から始めます。
2. 一覧のカテゴリと語彙を見渡し、語彙へポインターを置くかクリックして、別枠の効き方と作例を読みます。
3. 語彙を選ぶと、本文の選択範囲またはカーソル位置へ挿入します。

`おもて`の11語には、面の在り方を示す小さな絵と、描画への効き方の説明が付きます。絵はどの語も同じ輪郭を共有し、変わるのはその内側だけです。

歳時記は自動補完ではありません。必要なときだけ参照し、記述を既存語彙へ自動的に狭めません。語彙を選ぶだけでは描画は始まりません。

プラグインの語も、組み込みの語と同じ見え方で同じ列に並びます。説明は語の下ではなく、一覧とは別のプレビュー枠に出ます。プレビューは題、効き方、作例、絵の4つで、絵はプラグイン文書が同梱している場合だけ出ます。絵のない語は組み込みの語と同じ落とし先の絵になります。

## 6. 指示書を確認する・編集する

生成後、左側の指示書の欄に、Stage 1が入力をどう読んだかが表示されます。

- 記述: 人間が書いた言葉
- 写生（Stage 0.5）: 記述を物の言葉へ写した自然文
- 指示書（正規化DDL）: コア語彙へ整理された描画指示
- 展開後（Stage 2入力）: プラグイン展開と拡張層が補ったあと、Stage 2が実際に受け取ったDDL
- JSON Score: Stage 2が作る機械可読な楽譜
- 作品: Rendererが作るSVG

左側の指示書の欄と指示書エディタの見出しは、その指示書を読む言語で`指示書（日本語DDL）`か`指示書（英語DDL）`になります。エディタでは書いている本文から判定し直します。数値の範囲などの書き方は日本語と英語で違い、指示書はこの言語の文法で読まれます。平仮名・片仮名・漢字が1字でもあれば日本語DDLになるので、英語の指示書に日本語の名前が1つ入るだけで日本語として読まれます。

`自動補正`で、不可視色、過密、契約違反などの決定的な補修を有効または無効にできます。補正の内訳は、背景と同化する色の可視化、過密な線・粒・塗りの抑制、欠けた形状パラメータの補完、重複した命令の整理、不正な接触・位置関係の除去、DDLに書かれた色や形の不足補完、構図の支点・動き・リズムの補完です。

指示書には二つの入口があります。どちらも同じダイアログと編集欄を使います。本文は行番号、構文の色分け、行数・文字数を示し、描画モデルと編集時の`暴れる`は本文の外で選びます。描画中は本文、歳時記、条件変更、閉じる操作が止まり、失敗または停止しても入力内容は残ります。

| 操作 | 内容 |
|---|---|
| 指示書を新規作成 | `記述`側から開く。記述を介さず、空の指示書を直接書いて独立した作品として描画する |
| 指示書を編集 | 表示中作品の指示書見出し横、または作品の編集メニューから開く。本文を編集し、その子として描き直す |

`指示書から描画`は、表示中の指示書をそのままStage 2へ渡して描き直します。Stage 1は走らないので解釈は変わりません。

### 実在しないプラグイン名は、書いている最中に分かります

`Nature.青葉`のような`名前空間.語`は、そのサーバーに登録されている正式名だけがプラグインの色で示されます。**登録されていない名前は別の色になり、エディタの下に理由が並びます。**

- **その語が発火語なら、外し方を案内します。** `Nature.菖蒲`は`「Nature.」を外すと「下草」として効きます`と出ます。`菖蒲`は`Nature.下草`を発火させる語で、正式名のほうが存在しないためです。
- **発火語でもなければ**`この名前は登録されていません`と出ます。
- **色は「間違い」ではなく「注意」です。** プラグインは後から足せるので、今日無い名前が明日は有効になりえます。
- **⚠ 実在しない正式名は、その文ごと失われます。** 展開層が`名前空間.`を剥がすとき、その文を警告付きで取り除くためです。**描いた後にも同じ警告が作品の下に残ります。**
- **ドットの付かない語は今までどおりです。** `菖蒲`とだけ書いた場合は普通の語として扱われ、色は変わりません。

### DDLを編集した作品の記述は固定されます

指示書（DDL）を編集した作品は、記述ではなくDDLで決まっています。記述から描き直すとDDLの編集が失われるため、**記述は固定されます**。

- 記述タブの見出しに`固定（DDL編集済み）`と出て、記述の欄は書き換えられません。`描画する`の代わりに`この記述から新しい作品を作る`が出ます。押すと、記述をそのまま使って新しい作品として描き直します（元の作品はそのまま残り、記述は新しい作品で書き換えられます）。
- 作品の編集メニューの`記述を変える`、`写生なし／ありで描き直す`、`モデルを変える`は、理由を添えて押せなくなります。推敲の`読み取りを変える`も使えません。
- タッチ、配置、色で作った子もDDLを受け継ぐので、同じく固定されます。記述を読み直して作った子は固定されません。
- 履歴の帯では錠の印、系譜のカードでは`固定（DDL編集済み）`の印で分かります。
- AIに推敲させる場合は、読み取りの世代とAI Visionの方式を使わず、色・配置・タッチの世代をDDLから描きます。

## 7. モデル、色カタログ、写生、暴れる、キャンバスを選ぶ

記述タブの`次に描く条件`は次の生成に使われます。入力タブは`記述`と`バッチ`です。バッチには同じ種類の条件を、そのバッチ専用の`次のバッチの描画条件`として表示します。

| 操作 | 内容 |
|---|---|
| モデル | Stage 1とStage 2の両方に使う描画モデルを選ぶ |
| 色カタログ | `赤`、`青`、`灰`などの抽象色名を実色へ対応付けるカタログを選ぶ |
| 写生 | Stage 0.5の区切りを選ぶ（§4） |
| 暴れる | 筆致の天井を外す |
| キャンバス | 縦横比を選ぶ |

描画にはStage 1とStage 2で同じモデルを使います。段ごとに測ってあるモデルは、低いほうの段の順に並びます。画像を読むVision処理のモデルは別に選びます。

色カタログには`記述から自動選択`があります。選ぶと、描くたびにサーバーが記述を読んでカタログを決めます。選択はユーザーごとに保存されます。

作品は、描かれた当時の色を自分の行に記録します。そのため**過去の作品を描き直すと、カタログの今日の定義ではなく当時の色で描かれます**。カタログの名前が変わっても、そのカタログが廃止されていても描けます。状態表示のカタログ名には、廃止されたカタログなら`引退済み`が、色の記録を持たない古い作品なら`当時の色は記録がない`が添えられます。後者は現在の定義で描かれます。

`暴れる`はOFFが予想のつく標準、ONは奔放に折れ・巻き・重なりが出ます。作品全体に効き、作品へ記録されて再現されます。

キャンバスは9種類です。

| ID | 比率 | 由来 |
|---|---|---|
| Square | 1:1 | 標準仕様。完全な秩序を象徴する正方形 |
| Golden | 1.618:1 | 西洋美術における伝統的な美の比率 |
| A4 | 1:1.414 | 印刷規格のルート長方形 |
| B4 | 1:1.414 | 印刷物の身体感を持つルート長方形 |
| Pillar | 1:5 | 柱絵。縦長の余白と書き下ろしの感覚 |
| Oban | 2:3 | 浮世絵木版画の標準的な比率 |
| Wide | 2.35:1 | シネマスコープ。パノラマや情景の提示 |
| Byobu | 2.2:1 | 日本の屏風。六曲一双の一隻に準じる横長の型 |
| Vertical | 9:16 | スマートフォン全画面の現代的な型 |

キャンバスが変わっても座標は0.0〜1.0に正規化されます。**痕の大きさはキャンバスの短辺を基準に決まるので、同じ記述はどの比でも同じ形の痕を描きます**（横長に書いた楕円は柱絵でも横長のままです）。**痕を並べる形も同じ基準で決まります** —— 放射状に並べた環は、どの比でも同じ丸さで描かれ、正方形として述べた領域は正方形のまま扱われます。**まとまりで散らしたときの一かたまりの形と、道筋（波・斜め・上から下）の振れ幅も同じです**。置き場所・領域の中心・まとまりの中心は比に応じて広がり、**道筋が紙のどこまで伸びるかも比に応じたままです**。キャンバス比率はシステム標準プラグインなので、管理者が無効にすると正方形だけになります。

**v2.13.14から、選んだキャンバスは構図を組む段（Stage 2）にも伝わります。**構図はどの紙に描くのかを知って組むので、同じ記述でも柱絵と屏風では違う置き方になります。**紙に合わせて動くのは大きさと配置だけです** —— 記述が数を述べていればその数のまま描かれ、記述が大きさを述べていれば紙の都合で変えられません。

表示中作品の実設定と、次の生成に使う設定は別です。作品側の`表示中作品の条件`は選択した保存済み作品が描かれたときの記録で、入力側の`次に描く条件`はこれから描く作品に使います。ライブラリで作品を閲覧するだけでは次に描く条件は変わりません。両者が違っていてもエラーではありません。

## 8. 推敲する

作品タブの推敲欄で、一度に変更する要素を一種類だけ選びます。

| 推敲要素 | 変わる範囲 | 費用 |
|---|---|---|
| 配置を変える | 指示書の［構図］の範囲を選び直す。明示したかたむきの角度と「隅」も候補のseedで選び直す | 高速（範囲の選び直しはLLM不要。従来の補完は指示書に穴が残るときだけ） |
| 読み取りを変える | Stage 1から読み直し、指示書、配置、タッチを再生成する | 低速（LLM） |
| 言葉でタッチを変える | 入力語からRendererのperformance seedだけを決め、線質、太さの揺らぎ、滲みを変える | 超高速（LLM不要） |

`1案を作る`または`4案を作る`を選べます。「言葉でタッチを変える」は同じ言葉が同じタッチ（Seed）になる決定的操作なので、1案だけ生成できます。語句は作品の意味、読み取り、DDL、JSON Score、配置には作用しません。

色カタログは、ここではなく作品編集メニューから変えます（8.3）。

「配置を変える」の下で「原理に沿う」か「偶然に委ねる」を選びます。既定の「原理に沿う」は指示書から分かることだけで別の構図を解き、「偶然に委ねる」は層の種類が許す範囲から選びます。保存した指示書を使うので、記述が無い作品でも候補を作れます。［構図］の範囲以外の文字と元の作品は変えません。

候補には `1: 右下 → 左上` のように層番号と動きを表示します。選び直せないときは「この作品には構図の範囲が無い」「組み合わせが多すぎて別の構図を探せない」などの理由を表示し、保存した指示書をそのまま組み直します。構図の印も、明示したかたむきや隅も無い作品では、同じ絵になることがあります。候補を保存すると、系譜の「構図」の辺へ構図seedと選んだモードを記録します。

### 8.1 変奏（廃止）

変奏は 2026-10-04 に廃止しました。焦点の読み替えを外してから動かすものが無く、推敲と紛らわしかったためです。前に変奏で作った作品の系譜には「変奏（旧）」の辺が残り、その作品の生成情報には当時の変奏 seed と強度が出ます。

### 8.2 候補の保存

候補は未保存です。候補の選択操作で採用対象を選び、`選んだ候補を保存して閉じる`で履歴へ保存します。選ばなかった候補は破棄されます。どれも残さないときは`すべて破棄して閉じる`を使います。未保存の候補があるうちは、×・背景・Escでは画面が閉じず、この2つのどちらかを選ぶよう表示されます。ページを再読み込みしたりタブを閉じたりすると、ブラウザの確認が出ます。

候補を押すと、画面の中で大きく表示されます。`一覧へ戻る`か、もう一度押すと一覧に戻ります。保存とスターは別の操作です。保存した候補には、選んだ理由を任意で残せます。

### 8.3 色カタログを変える

作品編集メニュー（作品タブの`推敲する`、系譜タブの各作品の`…`）から`色カタログを変える`を選ぶと、専用の画面が開きます。開くとすぐ、いまの色カタログを除くすべての色カタログで同じ作品を描いた候補が、色カタログの一覧の順に並びます。DDL、JSON Score、配置、タッチは変わらず、LLMも呼びません。候補の下には色カタログの名前が出ます。

候補の選び方と保存・破棄は8.2と同じです。途中で止めたときや描けなかったときは、`ほかの色カタログで描く`で描き直せます。保存済みのJSON Scoreだけを描き直すので、記述の無い作品（DDLを直接書いた作品）でも候補を作れます。

## 9. AIに推敲させる

系譜タブから、AIに世代を重ねさせることができます。

| 推敲方式 | 内容 |
|---|---|
| ランダムな自動推敲 | 選択した要素からランダムに世代を重ねる |
| AI Visionによる自動推敲 | 画像を観察し、次に試す方向を各世代へ渡す |

世代数と、使用する推敲要素を選べます。方向性（プロンプト）を書くと、AI Visionでは各世代へ渡り、ランダムな自動推敲では「読み取りを変える」世代にだけ反映されます。「読み取りを変える」を外すと反映されません。

どちらの自動推敲でも「配置」の世代は、親の保存した指示書を「原理に沿う」で組み直します。手動で「偶然に委ねる」を選んでも、この既定は変わりません。構図の範囲の選び直しはLLMを呼びません。

**AI Visionによる自動推敲で選んだモデルは、観察だけでなく各世代の描画にも使われます**（実行中の表示にも、いま描いているモデルの名が出ます）。ランダムな自動推敲はモデルを選ばないので、ページで選んでいるモデルで描きます。

ダイアログは、前回選んだ推敲方式、世代数、推敲要素、方向性の文を覚えていて、次に開いたときもその状態で始まります（使っているブラウザに保存します）。暴れるの指定は覚えず、推敲する作品に合わせて始まります。

写生は、始める作品に合わせます。写生ありで描いた作品からは、各世代もその写生文から描き、写生を呼び直しません。方向性を書き足した世代だけは記述が変わるので、写生を書き直します。写生なしで描いた作品からは、写生なしで世代を重ねます。記述タブの写生の設定は使いません。

## 10. モデルを変える

作品編集メニュー（作品タブの`推敲する`、系譜タブの各作品の`…`）から`モデルを変える`を選ぶと、専用の画面が開きます。画面の上に並ぶモデルから描くモデルを選び、`選んだモデルで描く`を押すと、選んだ各モデルで記述から描き直した候補が並びます。選んだ各モデルをStage 1とStage 2の両方に使います。片方の段を固定することはしません。色カタログとキャンバスは、対象の作品のものを使います。

選べるモデルは最大4つです。対象の作品が使ったモデルは選べません。過去の作品で両段のモデルが異なる場合は、どちらも選べません。過去の作品の記録はそのまま残ります。

描いている間は、色カタログを変えるときと同じく、マスコットがモデルごとの進み具合を示します。エラーを返したモデルは選択欄に`NG`と出て、件数が示されます。ほかのモデルの候補は残ります。別のモデルを選んでもう一度押すと、その候補が後ろに足されます。一度描いたモデルは描き直しません。

候補の選び方と保存・破棄は8.2と同じです。候補の右上の`+`で残す候補を選び、`選んだ候補を保存して閉じる`で履歴へ保存します。保存していない候補がある間は、画面を閉じられません。

## 11. 生成情報を確認する

作品タブ下部の生成情報を開くと、選択中作品の記録を確認できます。タブは`詳細`、`プロンプト`、`JSON`です。

`詳細`は六つの節に分かれます。

| 節 | 主な内容 |
|---|---|
| 写生 | 写生の記録、紙の目（**画面に出ている作品の記録**であり、次に描くときの設定ではありません） |
| 解釈 | Stage 1モデル、Stage 1言語、要求した言語、解釈seed、解釈フォールバック |
| 演奏 | Stage 2モデル、Stage 2言語、焦点・変奏（旧）・変奏（旧）seed（古い作品だけ）、配置seed、render seed、種テキスト、暴れる、この作品に実際に当たった色語、色カタログ、キャンバスと比率、作曲フォールバック、**絵の重さ3行**（`SVG サイズ`／`SVG オブジェクト数`／`SVG 点数`） |
| 同一性 | render hash、記述hash、render engine、DDL仕様、変換層、各プロンプトdigest、Build |
| 由来 | 世代、派生、バッチ実行IDと行番号、コメント、UI言語 |
| 実行 | 経過時間、token数 |

各項目には意味の説明が付きます。たとえばrender seedは「演奏の揺らぎを固定する種。同じ種・同じScoreなら同じ絵になる」、記述hashは「記述の指紋。同じ言葉から来た作品を束ねる」です。

**絵の重さは3つの量で出ます。**`SVG サイズ`はデータ量、`SVG オブジェクト数`はSVGが持つ図形の数（入れ物と注記＝svg・defs・title・desc・metadataは数えません）、`SVG 点数`はその図形が持つ点の数です。**3つは互いの代わりになりません** —— 同じデータ量でも、図形が少なく点が多ければ線の細かい絵、図形が多く点が少なければ形の多い絵です。

`プロンプト`はStage 1／Stage 2のシステムプロンプトとユーザー入力、`JSON`はJSON Scoreを表示します。システムプロンプトは、その作品を描いたときに実際に送ったものです。プラグインや写生の有無、再試行によって作品ごとに変わります。モデルを呼ばなかったStage（直接書いたDDLのStage 1、穴埋めが要らなかったStage 2）と、記録を始める前に描いた作品には、その旨を表示します。JSON Score本体と生成情報を混同しないでください。

Stage 1が時間内に答えなかった、空を返した、あるいは失敗した場合は、定型の代替DDLで描画し、`解釈フォールバック`として理由を記録します。

**Stage 2（作曲）が同じように答えなかった場合も、定型の手順で演奏し、`作曲フォールバック`として理由を記録します。**どちらの場合も作品に印が付き、**両方が落ちた作品には印が2つ並びます**。生成情報の`作曲フォールバック`は3通りの答えを返します —— `あり`（落ちた）、`なし`（落ちなかった）、`記録なし`（この記録が始まる前に描かれた作品）。**`記録なし`は「落ちなかった」という意味ではありません。**

**印の付いた作品を選んで推敲しようとすると、実行の前に一度だけ確認が出ます。**その作品は言葉との対応が切れているので、そこから先を続けるかどうかを尋ねます。同じ作品について二度は尋ねません。

## 12. 系譜をたどる

`系譜`タブは、作品がどの明示操作から派生したかを表示します。タッチ、配置、読み取り、モデル、言語、DDL編集、記述編集、再描画、キャンバス変更、写生の区切りなどが親子関係として記録されます。変奏で作った古い作品には「変奏（旧）」の辺が残ります。

- 見た目の近さ、同じ記述、時刻だけから親子関係を推測しません。
- 中間作品は`lineage_only`として系譜にだけ残り、通常履歴には出ません。昇格させると通常履歴へ移ります。
- 系譜カードから、通常履歴への昇格、コメント、スター、推敲マーク、ごみ箱操作ができます。
- 系譜から作品を選び、記述や指示書を使って描き直すこともできます。

## 13. 奥書を読む

`奥書を読む`は、表示中の作品までの枝を、一人称の読み手として朗読させる機能です。起点から表示作品までの世代を順に読み、世代ごとに見えた変化と全世代の不変量を記します。

- 評価や選別ではありません。生成、推敲、枝の選択へ接続してはいけません。
- 読み手モデルを選べます。読みは追記され、編集されません。削除は可能で、削除後は戻せません。
- 観察語彙から外れた表現があると警告が出ます。

## 14. 履歴を管理する

下部の履歴ストリップは時系列での高速な前後移動に使います。履歴の入口を開くと、制作画面とは別の`ライブラリ`になります。`制作に戻る`で戻っても、入力、推敲の一時状態、ライブラリの検索・絞り込み・表示形式・ページ・選択・スクロール位置・閲覧用プレビューを保ちます。

ライブラリでは`表示形式`（`サムネイル`／`リスト`）と`まとめ方`（`時系列`／`系譜ごと`）を別々に選びます。行または画像を選ぶ閲覧用プレビューは、次に描く条件を変えません。対象を開く入口は`作品で開く`、`系譜で開く`、`推敲する`です。

`サムネイル`と`系譜ごと`を組み合わせると、系譜ごとの枠に起点から世代順で作品が横へ並びます。系譜の一覧は縦に、長い系譜の作品列は横にスクロールして見渡せます。

**サムネイルの下に添える情報は、`設定`の`表示と操作`で選べます**（`履歴帯に添える情報`）。世代・モデル・engineバージョン・ファイル容量の4つから**最大2つ**まで選べ、**何も選ばなければ絵だけが並びます**。3つ目を選ぼうとすると、既存の選択は追い出されず、上限が示されます。**ファイル容量はサーバーが報告する保存済み作品の容量**です。

- 検索（記述、ハッシュ値の下位4桁、または**全長のrender hash**）
- スターのみ、推敲のみ、共有のみの絞り込み。併用すると、選んだすべてに該当する作品だけになります
- 通常履歴とごみ箱の切り替え
- サムネイル表示とリスト表示。リストはハッシュ、日時、モデル、所要時間、色カタログを一覧で比べます
- 個別または複数選択によるごみ箱移動、復元、完全削除
- 系譜単位の展開と一括選択
- 表示中作品への同期と、最古／最新ページへの移動
- **移動の語はどこでも「新しい・古い」で一致します。**キャンバス・ストリップ・ライブラリのどこを見ても、左が新しい方・右が古い方で、「前」「次」「最初」は使いません（`←新しい`／`古い→`／`最新`／`最古`）

`系譜ごと`は保存済みlineage node／edgeだけを根拠にグループ化します。`lineage_only`の中間作品とtombstoneは通常履歴件数へ含めません。

推敲マークはスターとは別の印です。あとで手を入れたい作品に付けます。

共有の印は3つ目の印です。作品タブのキャンバス下部にある`共有対象にする`で立てます。**立てると、自分と同じ組織グループの人がその作品を読めるようになります。**もう一度押すと下ろせます。管理者は別の組織グループを宛先に選べます。

**印を下ろしても宛先は残ります。**同じ作品にもう一度印を付けると、前と同じ相手へ戻ります。**この印が広げるのは読むことだけで、書くことは広がりません** —— 共有された作品にスターを付けたり、ごみ箱へ移したりはできません。系譜の節点はこの印に従って見えますが、**奥書は付いてきません**。

履歴ストリップと`ライブラリ`の両方に`共有のみ`の絞り込みがあり、印を付けた作品だけを並べられます。

`再現`は、保存済みScoreとseedで再レンダリングします。作品を描いたengineの版が現行と違う場合は、その旨と両者の比較が表示されます。render seedを持たない古い履歴は再現できません。

## 15. 画像を書き出す

作品タブ下部の`書き出す`を開き、対象が`表示中の作品`であることを確認して、SVGの形式またはPNGのサイズを選びます。ライブラリや系譜の書き出しでは、メニューに表示される選択件数または起点からの経路を確認してください。メニューの`SVG保存形式の違い`の`?`で、下の表と同じ説明を開けます。

書き出せるのは保存した作品だけです。保存していない絵（デモで保存を切って描いたものなど）は、先に保存してから書き出します。シンプルUIでは、`書き出す`のボタンが`共有カード`だけを直接書き出します。

| 形式 | 用途 | 特徴 |
|---|---|---|
| 表示用（Display） | Web表示・PNG生成 | 保存済みSVG。見た目の再現を優先し、filter / clip-pathを使う |
| 編集用（Editable） | Illustrator / Affinity | Scoreから再生成。レイヤー構造と安定IDを付け、filter / clip-pathを避ける |
| 互換優先（Compat） | 汎用SVG受け渡し | Scoreから再生成。編集用に近いが、壊れにくさを優先する |
| ライブ用（Live） | VIA2等の映像ソフト | Scoreから再生成。編集用の構造に表示用の質感とタッチを持つ。命令ごとに描き進めるソフト向けで、ふつうの閲覧には表示用のほうが軽い |
| PNG | 指定解像度のラスター画像 | 標準、高解像度（2×）、正方形、正方形高解像度。テンプレートは設定で増やせる |

`編集用`・`互換優先`・`ライブ用`はScoreから描き直しますが、**描き直しは保存されたときの演奏を使います**（保存された作品が持つrender seedと配置seedの両方を渡します）。**保存済みSVGとの違いは、描画エンジンの版が進んだぶんだけです** —— inkuは過去の版を保持しないので、版が進んだあとの描き直しが1バイト一致することはありません。

保存先フォルダは`設定`→`エクスポート`→`保存先`で指定できます。指定しなければブラウザの既定のフォルダへ落ちます。フォルダそのものはそのブラウザの中にだけ残るので、別のブラウザや別の端末では選び直しになります。書き込みが許可されなかった場合はブラウザの既定へ落ち、その旨が表示されます。

### 15.1 コンタクトシート

ライブラリで選択した作品を1枚のPNGへ並べます。

| 種類 | 内容 |
|---|---|
| 人用コンタクトシート | 1枚あたり7×4点。超過分は別ファイル |
| AI用コンタクトシート | 1枚あたり3×4点、長辺1568px、キャプションは連番のみ。番号・記述・DDL・来歴を収めたmdも同時に保存 |

### 15.2 共有カード

作品を1枚のカードとして書き出します。絵・詞書・render seedの下4桁・刻印を1枚に組みます。詞書が空の作品は絵だけのカードになり、render seedを持たない作品はseedの行が出ません。

書き出す口は2つあります。

| 口 | 対象 | 押したときの動き |
|---|---|---|
| 作品タブ下部の`書き出す`の中の`共有カード` | 表示中の作品 | 押すとすぐ1枚を書き出します |
| ライブラリ・系譜の`書き出す`の中の`共有カード` | メニューが示す1作品 | 選択またはプレビューの対象が1件のときに使えます |

どちらも版面と刻印は同じ設定に従います。まだ保存されていない作品にはカードがないので、キャンバス側のボタンは押せません。

**シンプルUI（および`推敲・比較・書き出し・作品操作`を外したカスタムUI）では、作品側の書き出し口はカード専用のボタンになります。**押すとメニューを出さずにカードを書き出します。SVGとPNGはこの群に属する道具なので出ませんが、カードは作品を他人へ渡す道なので残ります。

| 設定 | 選択肢 |
|---|---|
| 版面 | 正方形（1080×1080）、縦長（1080×1350） |
| 刻印 | 付ける（既定）／付けない |

組版はサーバーが行い、同梱フォントで焼きます。閲覧している機械にどの書体が入っていても、出てくる文字は同じです。絵は画素として貼らずSVGのまま入れ子にするので、最後の1回のラスタライズまでベクターで残ります。詞書が長い場合は絵の枠が縮み、6行を超えた分は`…`で切ります。

CLIからは`inku-cli export-card`で同じカードが出ます。

### 15.3 アニメーション

保存済みの1作品と、複数の選択作品では書き出し方が違います。表示中作品またはライブラリで1件だけチェックした場合は、`書き出す`から`レイヤーアニメーション`を選びます。複数作品をチェックした場合は`作品をつなぐアニメーション`を選び、作品を古い順で切り替えます。系譜では、起点から表示中作品までの経路を出す操作と、チェックした作品だけを出す操作を使い分けます。

| 設定 | 選択肢 |
|---|---|
| フォーマット | PNGアニメーション（APNG・可逆圧縮）、GIFアニメーション（256色） |
| 切り替えパターン | カット、クロスフェード、白を介したフェード、横スライド |
| 表示ウェイト | 各作品を表示する秒数 |
| 解像度（Y軸） | 150px、300px、500px、1K（1080px）、4K（2160px）、8K（4320px）、任意指定 |

1作品では`レイヤーの分割枚数`で地から完成までの前進フレーム数を決めます。レイヤーは各フレームで累積して完成へ進みます。`レイヤーの間隔`で各フレームを表示する秒数を決めます。これは保存済みSVGの重なりから作る疑似制作過程です。

| 繰り返し方 | 動き |
|---|---|
| 最初に戻る | 完成したら地へ戻り、再び積み上げる |
| 逆に再生する | 完成から地へ逆再生し、往復する |
| 最初だけ再生する | 一度だけ積み上げ、完成した状態で止める |

複数作品では切り替えパターンと各作品の表示ウェイトを設定します。形式・解像度・保存先は両方に共通です。書き出しモーダルで変えた設定と保存先は今回だけに適用します。対応するブラウザでは`保存先パスを指定`でフォルダを選べます。選べないブラウザはブラウザのダウンロード設定を使います。

ライブラリからは古い順に並べ、系譜からは起点から選択作品の順に並べます。

## 16. バッチ

1. `バッチ`タブを開きます。
2. 一行に一つの記述を入力します。
3. `描画する`を押します。

処理中は現在行、進捗、経過時間、token数、処理中の指示書を表示します。失敗行はレポートから確認でき、成功した作品は履歴へ保存されます。作品にはバッチ実行IDと行番号が記録されます。

過去に使ったバッチ記述は`バッチ記述履歴`から復元できます。直近50件を保存します（v2.13.21・それ以前は20件）。一覧はウインドウの高さの半分までで、入りきらないときはスクロールします。一覧の外を押すか`Esc`を押すと閉じます。

途中で`停止`したバッチは、`中断したバッチを再開`の`中断時点から再開`で続けられます。元のバッチの未完了行を確認し、完了した作品は描き直さず、元の入力と描画条件を復元して続けます。処理中の停止だけでなく、ブラウザを再読み込みした後も、サインインしたアカウントにある最新のバッチ記述と保存済みのバッチ作品から中断を確認できれば再開できます。履歴や記述から未完了を確認できない場合は再開カードは出ません。

設定の`バッチの再試行`を1以上にすると、一巡したあと失敗した行だけをもう一度描きます。0なら再試行しません。途中で中断したときは再試行しません。

## 17. デモ

`設定`→`制作`→`デモ`から開きます。シードフレーズから短い記述を生成し、その記述で描画を繰り返します。DB保存、ファイル保存、記述生成モデル、表示間隔（秒）、タイムアウト（分）を設定できます。

開始すると設定が閉じ、キャンバスで進行を見られます。実行中は制作画面に停止操作と`デモの設定・進行状況`が表示され、設定を開き直せます。記述・バッチの入力本文は保持されます。

自動保存を無効にした場合でも、気に入った現在作品を明示的に履歴へ保存できます。設定した時間に達すると自動停止します。デモ実行中は履歴操作をロックします。

## 18. 設定

アプリレールの`設定`から開きます。設定は`表示と操作`、`制作`、`エクスポート`、`接続と管理`、`拡張と詳細`に分かれます。役割によって見えるページと操作が変わります。

| カテゴリ | ページと内容 |
|---|---|
| 表示と操作 | `表示と操作`。文字サイズ、詞書の位置、UIモード、履歴帯に添える情報、マスコットなど |
| 制作 | `バッチの再試行`と`デモ` |
| エクスポート | `エクスポート`。保存先、PNG保存テンプレート、アニメーション、共有カードの版面と刻印 |
| 接続と管理（管理者） | `モデル設定`、`ユーザー管理`、`DB設定`、`ログ保存`。`詳細`では`その他（サーバー）`と`制限値`も表示する |
| 拡張と詳細 | `詳細`で`プラグイン`と`未読語台帳`を表示する |

描画に使うモデルは、制作画面の描画条件から`モデル選択`を開き、`Stage 1/2`で選びます。画像を読むモデルは、必要に応じて`Vision`で別に選びます。管理者向けの`モデル設定`は、接続先や公開するモデルを管理するページです。公開されているモデルが無い用途では、`モデル選択`に「選べるモデルがありません。」と、管理者が公開すると選べることが出ます。選んであるモデルが公開の一覧から外れていると、そのidに`一覧にない`と添えて出ます。

設定ダイアログは`標準`と`詳細`の2つで、右上の`表示モード`で切り替えます。`標準`は日常的な設定を表示し、**`プラグイン`、`制限値`、`未読語台帳`、`その他（サーバー）`の4タブは`詳細`のときだけ出ます。**選んだほうはこのブラウザに残ります。

`表示と操作`の`文字サイズ`は90%、100%、110%、120%、130%の5段階です。動かすと直ちに画面へ反映し、操作を確定するとアカウントへ保存します。`標準に戻す`は100%へ戻します。保存に失敗しても表示中の大きさは保たれ、エラーの`再試行`で保存し直せます。作品のSVG、画像、書き出し寸法は変わりません。

`ユーザー管理`では検索、権限・所属なしの絞り込み、ユーザーの選択と編集を使います。追加フォームは`追加`で明示的に開きます。選択した利用者だけを編集し、権限とグループを設定して`変更を保存`します。未保存の編集がある間は一覧更新や選択し直しを行わず、保存に失敗しても入力内容とエラーを保ちます。Web UIで利用できるのは管理者です。

`制限値`は速度の調整ではなく、描かれる線の数そのものを変えます。ここで決めた値はStage 1／Stage 2のプロンプトへ書き込まれ、描いた作品ごとに記録されます。詳細は`サーバー設定方法`を参照してください。

**作品を描き直すときは、その作品が描かれたときの制限値が使われます**（v2.13.31）。今日の設定が使われるのは、制限値の記録を持たない古い作品だけです。**上限が実際に効いて痕を落としたときは、その上限の名前とともに絵の下に出ます**（プラグインの警告と同じ場所です）。ここも制限値と同じで、下げることはできても上げることはできません。

九つの数は三つの族に分かれ、**族ごとに従うべき相手が違います**（v2.13.28）。`この機械が描ける量`は設置した機材が一枚にどれだけ描けるかで、速い機械なら上げられる唯一の族です。`目で数えられる限界`はそのまま数えて描く数と群れとして見せる数の境目で、**機械が速くなっても人の目は速くならないので、上の族に連動させないでください**。`誤入力の番人`は誤入力と暴走を止めるためだけの数で、動かしても絵は良くなりません。各族の見出しにポインタを重ねると、その族が何に従うべきかが出ます。

`未読語台帳`は、記述からDDLへの解釈で直接対応を確認できなかった語の集計です。この台帳から辞書へ自動昇格することはありません。管理者は全体集計も見られます。

## 19. CLIから描く

CLIはWeb UIと同じ公開HTTP APIを使います。

```sh
cd cli
uv run inku-cli --base-url http://127.0.0.1:8100 login -u admin
uv run inku-cli --base-url http://127.0.0.1:8100 paint "青い線が左下から右上へゆるやかに波打つ" -o out --png --save-history
```

Web UIで選べる設定は、そのまま旗として渡せます。

```sh
uv run inku-cli paint "夜の霧が広がる" --sketch --sketch-grain coarse --wild \
  --catalog-mode auto --canvas-aspect byobu -o out --png --save-history
```

```sh
uv run inku-cli batch -f prompts.txt -o out --png --continue-on-error
uv run inku-cli history --limit 20
```

旗を書かなければサーバーの既定が使われます。サーバーの既定とWeb UIの既定は同じとは限りません。たとえば写生はサーバー既定が`切`、Web UIの既定は`細かく`です。旗の全一覧は`inku-cli リファレンス`を参照してください。

## 20. うまく描けないとき

| 症状 | 対処 |
|---|---|
| 意図と違う | 指示書を確認し、場所、数、形、素材を具体化する |
| 記述の読み替えが荒い | 写生を`細かく`にする。既に細かくなら`大きく`を試す |
| 画像が単調 | てざわり、ゆらぎ、配置、色を一つだけ足す。または`配置を変える`を試す |
| 線が整いすぎる | `暴れる`をONにする |
| 要素が多すぎる | `三本`、`十二個`のように数を明示する |
| 数を書いたのに減らされる | 設定の`制限値`で、そのまま描く上限を確認する |
| 生成が遅い | 実行中の表示が`再試行中（2/4回目）`なら、前の試行が時間切れになったか、使えない応答だった。providerの待ち行列を待つか、モデル選択で軽いモデルへ変える |
| エラーになる | 記述を短くし、一文一指示へ分ける。理由の括弧に「制限時間内に返りませんでした」とあれば、モデルが時間内に答えていない |
| 「サーバーに接続できません」と出る | APIが止まっているか再起動中。つながれば画面は自動で開き直す。長く続くときはサーバーの状態を確認する |
| 描画が拒否される | 同時描画数の上限に達している。少し待つ |
| 比較結果が残らない | 比較候補の`採用`またはスターで履歴へ採用する |
| 推敲の画面が閉じない | 未保存の候補がある。`選んだ候補を保存して閉じる`か`すべて破棄して閉じる`を選ぶ |

感情的な評価語だけでなく、観察できる物理語を書きます。

```text
黒い太筆の線を中央に一本置く。
灰の円を周囲に七個、少しばらつかせて並べる。
```
