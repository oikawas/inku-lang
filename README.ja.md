# inku

**一文を、絵にする。**

inku は、文や画像から、LLM と型付きコンパイラを使ってベクター画像（SVG）を生成するアプリケーションです。
LLM が出力するのは画像ではなく、**人が読める描画言語 DDL のコード**です。DDL はオリジナルのグラフィック記述言語で、MML（Music Macro Language）のようなコンセプトで絵画の記述を可能にします。文の解釈は、LLM がモデルごとに非決定的に行い、DDL を出力します。DDL による記述は、型付きコンパイラで決定的に描画されます。LLM を使いつつ、人間がコントロールできる創作環境を提供します。

## 特徴

| | 一般的な画像生成 AI | inku |
|---|---|---|
| 出力 | ラスタ画像 | **SVG**（拡大しても劣化しない。印刷にも Web にも） |
| 生成の中身 | ブラックボックス | **DDL のコード**として読める。一行直して再生成できる |
| 再現性 | 同じプロンプトでも結果が変わる | **同じ Score と seed から同じ SVG** |
| LLM の役割 | 画像そのものを生成 | DDL を書くところまで。その先はコンパイラとレンダラーが決定的に処理する |
| 語彙 | 無制限 | 図形・画材・位置・関係などの**有限の語彙**。どの語が使えるかは辞書で引ける |
| 履歴 | 生成画像の一覧 | 編集と再生成の**派生ツリー**。どの版から何を変えたかが残る |

## 抽象から具象まで

inku は抽象画の生成から始まりましたが（文を解釈させて、意味の分かる絵にするのは思いのほか難しいことでした）、いまは具体的なモチーフも描けます。

- **座標と寸法で書ける** — 「画面の横0.6、縦0.4の位置に、幅0.1、高さ0.3の…」のように、画面比で位置と大きさを指定できます。上の赤い傘の例がそれです
- **モチーフの語を足せる** — プラグインで語彙を追加できます。「水流」「海」「雨」「若葉」のような情景の語は、定義した絵をそのまま描きます。「星」のような物の語は、図形と同じように位置・数・大きさ・傾きを指定して置けます（`中心に、｛星｝を3個置く。`）。プラグインの中身は、普通の DDL の形へ展開される語の定義（マクロ）です
- **構図を組める** — LLM が、絵画・デザイン・音楽の一般的な法則から構図を選び、モチーフの位置と大きさを決めてから DDL を書くこともできます
- **画像から始められる** — Vision 対応モデルが写真や絵を見て DDL を書きます。DDL でどんな表現が可能か、手軽に試せます。結果は編集できる DDL として残ります

プラグイン見本「水」の出力です（琳派の流水と日本画の波紋を参照）。→ [プラグインの作例](docs/plugins/README.ja.md)

一方で、「美しく」「悲しげに」のような評価や感情の語は、語彙に入れていません。DDL に書けるのは、見て確かめられること（形・画材・位置・動き・関係）だけです。これは DDL に LLM の非決定性を持ち込まないための、設計上の判断です。何を表現するかは書き手が決めます。

## 誰のためのものか

- **イラスト・デザイン** — 文からベクターのイラストを起こし、DDL を直して作品として詰めていくことができます。SVG に出力して、ほかのアプリケーションで編集できます
- **ジェネラティブアート／クリエイティブコーディング** — コードの代わりに文で書くジェネラティブ作品用途に。seed による揺らぎ、11 種の画材（鉛筆・水彩・油彩・エッチングなど）を描き分けるブラシエンジン、7 種の紙やキャンバスの質感、13 本の色カタログを材料にでき、バッチで大量の試作が可能
- **言語処理系・コンパイラ** — 日英どちらでも書ける自然文の DSL として構築しています。ソース位置を保持した型付きの意味表現、読めない句を推測で埋めず、診断付きでその句だけを除外するエラー回復が実装されています。→ [SPEC.ja.md](SPEC.ja.md)
- **LLM アプリ／エージェント開発** — 非決定的な LLM と決定的なプログラムを交互に挟む構成。JSON Schema の構造化出力で LLM の出力を語彙の範囲に縛る設計。全 API を操作できる CLI。→ [アーキテクチャ](docs/architecture/README.ja.md)
- **短歌・詩を書く人、詩歌の読者** — 歌や詩をそのまま入力にして、その世界をビジュアル化できます。LLM と組み合わせることで、一つの文から様々なイメージを引き出せます。このページのキービジュアルと「一行ずつ積み上がる」の作例は、古典の和歌と短歌から描いています

## アーキテクチャ

```
  入力                       LLM（非決定的）
  ───────────────────────────────────────────────────────────────
  文 ───┬─ 直接生成      文を読み、DDL を書き、レンダリング結果を見て一度修正
        └─ 構造化生成    JSON Schema で縛った構造化出力から、DDL を機械的に生成
  画像 ─── Vision 対応モデルが画像を見て DDL を書く
  手書き ─ ユーザーが DDL を直接書く
                    │
                    ▼
  DDL               人が読める・編集できるソース。ここから先は決定的
                    │  型付きコンパイラ
                    │  （解釈できない句は LLM が補完案を出し、ユーザーが承認する）
                    ▼
  Score（JSON）      DB に保存される中間表現
                    │  レンダラー
                    ▼
  SVG
```

**LLM が関わるのは DDL を書くところまでです。** DDL から先は常に決定的で、同じ Score・同じ seed・同じ描画条件からは同じ SVG が出ます。seed を変えると、線の震えや配置が少しずつ違う SVG になります。

**生成モードは二つあります。** Web の既定は直接生成（UI の表示は「言葉で描く」）です。LLM が文の背景を推察し、絵を構成し、位置と大きさの数値まで含めて DDL を書きます。結果は、より具象的な絵になります。構造化生成（「型で描く」）では、文をより機械的に捉え、LLM は語彙の enum だけで組んだ JSON を返し、DDL はそこから機械的に生成されます。結果はより抽象に寄ります。

解釈に使うモデルは選べます（OpenAI・Anthropic・Gemini・ローカル LLM）。どのモデルもアプリには含まれず、API で呼び出します。ChatGPT プラン（サブスクリプションの利用枠）でも使えます。モデルが変わると、出力は大きく変わります。

コンパイラ、Score、レンダラー、生成の状態遷移は **Rust の共有コア**にまとまっていて、サーバー（Python）、Android（Kotlin）、macOS（Swift）が同じコアを呼びます。同じ DDL は、どの環境でも同じ結果になります。

→ Score の実物と各層の詳細は [しくみの詳細](docs/guide/how-it-works.ja.md)、実装の境界は [アーキテクチャ文書](docs/architecture/README.ja.md) にあります。

## DDL

```
背景を青で埋める。
和紙。
白いガッシュの線を横に四十本並べる。
線はゆるやかに揺れる。
右端に赤い鉛筆の線を1本引く。
```

設計方針：

1. **人が読める** — 自然言語とプログラミング言語の中間に置く
2. **見て確かめられる語だけを持つ** — 評価語・感情語は持たない
3. **解像度に依存しない** — 位置と大きさは画面に対する比で書き、ピクセル値を持たない。作ったときの縦横比は「画面比1:1。」で宣言でき、別の比のキャンバスにも描ける
4. **出力は静止画**
5. **ランダム性を仕様として扱う** — LLM の解釈と、レンダラーの seed による揺らぎを許容する
6. **自由文は直接実行しない** — いったん DDL に変換し、型付きコンパイラで検証する
7. **レンダラーは後方互換を持たない** — 下の「レンダラーのバージョン方針」

### 画材の語を替える

DDL の画材の語を一つ替えると、同じ形が別の描き方になります。下のアニメーションは、DDL の画材の語（ガッシュ 23 か所、水彩 9 か所）を、コマごとにすべて同じ一つの画材に替えて描き直したものです。画材の語のほかは同じ DDL で、LLM は関与していません。


## 編集と派生履歴

<table><tr><td><img src="docs/assets/ui/describe-and-paint-dark.ja.png" width="900" alt="画面左に記述の入力欄と、その下に語ごとに色を付けた DDL。右の大きなキャンバスに、青地を白い線が交差する作品が表示され、最下段に履歴のサムネイル列が並ぶ"></td></tr></table>

最初の出力は、たたき台です。DDL を直す、色カタログを替える、配置を引き直す。候補から一つ選ぶと、それが次の編集の親になります。親子関係は**派生ツリー**として保存されます。

| 操作 | 変わるもの | 変わらないもの | LLM |
|---|---|---|---|
| DDL を編集 | 編集した行 | ほかのすべて | 呼ばない（解釈できない句の補完案を求めるときだけ呼ぶ） |
| 色カタログを替える | 色の割り当て | DDL・配置・揺らぎ | 呼ばない |
| 配置を引き直す | 傾きの角度、隅の位置 | DDL、画材・色・数 | 呼ばない |

どの操作も、ユーザーが明示的に行ったときだけ働きます。反復を AI に任せる自動モードもあり、その間の世代もすべて派生ツリーに残ります。→ [編集と派生の詳細](docs/guide/revision.ja.md)

## レンダラーのバージョン方針

レンダラーは過去のバージョンを持ちません。古い Score も最新のレンダラーで描けますが、結果は当時と変わります。後方互換のための分岐は持ちません。

その代わり、生成した SVG はそのまま保存されるので、当時の出力はいつでも見られます。再レンダリングすると、最新のレンダラーによる新しい版として保存されます。→ [レンダラーの版史](docs/spec/render-engine-history.ja.md)

## 実装の状況

| | 状況 |
|---|---|
| **Web**（SvelteKit + FastAPI） | 開発のマスターは、このサーバー版。マルチユーザー利用を含む、ほぼすべての機能が使える。カメラ機能はない |
| **CLI**（`inku-cli`） | 公開 API だけで、GUI でできることをすべて実行できる CLI。AI エージェントからの操作を想定 |
| **Android** | 配布中（[`android/VERSION`](android/VERSION)）。端末内で共有コアを呼んで生成。カメラ入力あり |
| **macOS** | 配布中（[`apple/VERSION`](apple/VERSION)）。Mac の中で共有コアを呼んで生成。署名・公証済みの `.dmg` で配布 |
| **共有コア**（Rust） | コンパイラ・Score・レンダラー・生成の状態遷移を実装 |

DDL は日本語と英語に対応し、作者が維持しています。Score の JSON は言語に依存しませんが、DDL は言語ごとの調整が要るため、ほかの言語を足す仕組みはまだありません。ほかの言語での貢献を歓迎します。

## 背景

2026年4月2日、東京都現代美術館の「ソル・ルウィット オープン・ストラクチャー」展で、DDL の最初の構想が浮かびました。LeWitt の壁画は、作家が書いた指示書をもとに、職人が壁に描きます。その職人の役をコンピュータが担えるのではないか、というのが出発点です。

| 着想の元 | inku に取り入れたこと |
|---|---|
| **Sol LeWitt の指示書** | 書かれた記述そのものを作品とみなす。記述する人と描く手を分ける |
| **盆栽** | 語彙を絞ったほうが、よい表現が生まれる |
| **短歌** | 短く、多くの意味を含む文を入力に想定する |
