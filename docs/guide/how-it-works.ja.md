# しくみの詳細

[README.ja.md](../../README.ja.md) の「しくみ — 楽譜と演奏」の続きである。楽譜の実物、各層の用語、
パイプラインの全体、面と地の質感、プラグイン語彙をここに置く。

## 用語と層

| 語 | 対応する層・行為 |
|---|---|
| **記述** | 作者が書く詩歌的な入力。作品の最上層（inku 固有。LeWitt に対応物なし）|
| **解釈** | 記述を指示書へ読み解く Stage 1 の行為 |
| **指示書（正規化DDL）** | 解釈が生む実行仕様。LeWitt の指示書に相当 |
| **楽譜（JSON Score）** | 指示書を構造化した中間表現。決定的に保存される |
| **演奏（SVG）** | 楽譜を描く一回性の結果 |
| **詞書** | 記述を作品の傍らに掲げ直したもの（短歌の詞書）|
| **読み取り** | 言葉の読み直しから候補を作り直す操作（別の解釈）|

## 一枚の作品を層で追う

README のギャラリー 2 点目「魚群の銀色」を例に、各層が何を持つかを見る。記述は次の一文だった。

```
戦争が終わった朝、対岸の狙撃手と漁師は、同じ魚群の銀色を見ていた。
```

解釈がこれを指示書（正規化DDL）に読み解く。狙撃手も漁師も戦争も残らない。残るのは図形・素材・運動の語だけである。

```
背景を白で塗りつぶす。
画面下半分に灰色の細筆の横線を二十本並べる。
中央付近に白い小さな楕円を百二十個、波打つ軌跡に沿って散らす。
右端に黒い鉛筆の縦線を一本引く。
```

構造化がこの指示書を楽譜（JSON Score）に書き起こす。実際に保存された楽譜の抜粋である（3 命令のうち魚群にあたる 2 つめ、`null` の項は省いた）。

```json
{
  "version": "0.1.0",
  "canvas": "square",
  "background": "white",
  "instructions": [
    {
      "primitive": "ellipse",
      "center": [0.5, 0.5],
      "size": [0.02, 0.01],
      "rotation": 18.0,
      "filled": false,
      "weight": "pencil",
      "color": "black",
      "variation": {
        "amplitude": "medium",
        "frequency": "slow",
        "quality": "wave",
        "dimensions": ["position_x", "position_y"]
      },
      "arrangement": {
        "count": 110,
        "layout": "scatter",
        "path": "wave",
        "color_cycle": ["black", "white"],
        "density": "high",
        "cluster_count": 7,
        "fade": "outward",
        "rhythm_spacing": "loose"
      },
      "surface": {
        "texture": "wash",
        "opacity": 0.6,
        "tone_steps": 3
      }
    }
  ]
}
```

「魚群」は `count` と `cluster_count: 7` に、「波打つ軌跡に沿って」は `path: wave` に、「銀色」は `color_cycle` と `surface.texture: wash` に落ちている。「対岸」は右端の一本の縦線になった。レンダラーがこの楽譜を演奏する——毎回わずかに違う形で。出力はベクターなので、額に入れても、壁一面に引き伸ばしても、手のひらの画面で見ても成立する。物理的なサイズの制約はない。

## パイプラインの全体

```
 あなたの記述（母語の自然文）
      │
      ▼
┌────────────────────────────────┐
│ Stage 1   解釈（LLM）           │ 自由な言葉 → コア語彙だけの指示書
├────────────────────────────────┤
│ Plugin   宣言的展開（決定的）   │ 名前空間付き語 → コア語彙だけの指示書
├────────────────────────────────┤
│ Stage 1.5 中間フィルタ（決定的） │ 構図族・焦点の選択、関係述語の付加
├────────────────────────────────┤
│ Stage 2   構造化（LLM）         │ 指示書 → JSON Score（楽譜）
├────────────────────────────────┤
│ Renderer  演奏（seed 駆動）     │ 楽譜 → SVG。揺らぎ・領域・関係を解決
└────────────────────────────────┘
      │
      ▼
 SVG（壁にも、紙にも、画面にも）
```

## 面と地の質感

楽譜には、面と地の質感も保持できる。円の内部を薄墨や点で満たす指定は `instruction.surface`、生成りの紙・和紙・薄墨地のような支持体は `canvas.ground` に入る。これらは抽象属性のまま保存され、Renderer が SVG filter、clip された vector mark、compat 向けの単純化出力として演奏する。

## プラグイン語彙

コアの外には、`Nature.風` のような名前空間付きの**プラグイン語彙**がある。プラグインはコードではなく検証済みの `.inku-plugin.md` 文書で、現象を一語で呼び出してコアDDLへ決定的に展開する。新しい図形・Score項目・任意コードを持ち込まず、削除後も保存作品のReplayとrh2は変わらない。ロード状態と拒否理由は設定画面、名前空間付き語とnoteは歳時記、管理操作は `inku-cli plugin list / validate / reload` で確認できる。
