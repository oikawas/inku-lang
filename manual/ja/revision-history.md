# マニュアル改訂履歴

この履歴は`manual/`配下の利用・運用文書の改訂を記録します。製品機能そのものの詳細な変更履歴は`SPEC.ja.md`を参照してください。

## 2026-08-11 — v2.13.3未リリース基準（Web Build 887）

版を名乗る13箇所をv2.13.3／Build 887へ更新し、**実在しないプラグイン名の扱いが画面に出るようになったことにあわせて`作品の作り方`§6に節を1つ足しました**。

- **実在しないプラグイン名が、書いている最中に分かるようになりました。** `Nature.青葉`のような`名前空間.語`は、そのサーバーに登録されている正式名だけがプラグインの色で示されます。登録されていない名前は別の色になり、エディタの下に理由が並びます。
- **発火語なら、外し方を案内します。** `Nature.菖蒲`は「「Nature.」を外すと「下草」として効きます」と出ます。発火語でもなければ「この名前は登録されていません」と出ます。
- **⚠ 実在しない正式名は、その文ごと失われます。** これは以前からの挙動で、今回変わったのは**それが書き手に伝わるようになった**ことです。**描いた後にも同じ警告が作品の下に残ります。**
- **⚠ 有効な正式名の見た目も変わりました。** `Nature.青葉`はこれまで`青`だけに色が付いていましたが、正式名を1語として扱うようになったため、いまは全体が1つのプラグイン語として示されます。
- **ドットの付かない語は今までどおりです。**

## 2026-08-11 — v2.13.2未リリース基準（Web Build 886）

版を名乗る13箇所をv2.13.2／Build 886へ更新し、**`inku-cli`に`history state`が増えたことにあわせて`CLIリファレンス`の副コマンド表に1行足しました**。

- **`inku-cli history state`が増えました。** 作品の総数と、最新の作品の時刻とIDだけを返します。**作品の絵は1バイトも読みません**ので、一覧を取り直す前に「変わったかどうか」だけを安く確かめられます。`--bytes`を付けると、応答が届いた実バイト数を添えます。
- **画面の作品帯が、12秒ごとに全件を取り直すのをやめました。** 先に「何が変わったか」だけを問い、変わっていなければ何もしません。**表示は今までどおりで、操作の手順は変わりません。**
- **タブに戻ったときの更新も、5秒の下限を通るようになりました。** これまでこの経路だけが下限を素通りしており、タブを行き来するたびに一覧を運んでいました。

## 2026-08-11 — v2.13.1未リリース基準（Web Build 885）

版を名乗る13箇所をv2.13.1／Build 885へ更新しました。**プラグイン参照の数え方が変わりましたが、マニュアルはプラグイン参照の書き方を扱っていないため、説明の追加はありません。**

- **プラグインを「三つ」と書けば、三つ置かれます。** これまではいくつと書いても1つでした。プラグインが渡すのは1つのまとまりで、同じ句に述べた数はそのまとまりを何回置くかを指します（**1つの中の内訳はプラグイン文書の宣言とseedが決めます**）。
- **⚠ 数はマクロ参照を含む句の中で読まれます。** 同じ文の別の句に書いた数は届きません（`、`または`,`が句の切れ目です）。
- **作品に入らない数は、切り詰めずに断ります。** 述べた数×1つ分が作品全体の上限を超えるときは1つのまま据え置き、その旨を作品の記録に残します。**中途半端な数を描くよりも、描かなかったと分かるほうを選びます。**
- **⚠ 英語の記述で、CJKを含む名前のプラグインを算用数字で数えると読まれません**（`Place 12 Nature.青葉 marks.`は1つ、`Place twelve Nature.青葉 marks.`は12）。算用数字の近くにCJKがあると日本語の道に譲る規則があるためで、**この扱いは未裁定です**。

## 2026-08-11 — v2.12.2未リリース基準（Web Build 879）

版を名乗る13箇所をv2.12.2／Build 879へ更新し、**作品を人に渡せるようになったことにあわせて`サーバー設定方法`§4、`inku-cli リファレンス`の履歴と管理の節を直しました**。

- **作品を1件ずつ、相手を選んで共有できるようになりました。** 渡す相手ごとに`read`（開ける）か`write`（星付け・ゴミ箱・削除もできる）を選べます。同じ相手に対して、作品ごとに違う権限を与えられます。
- **共有できるのは作品の持ち主と`admins`だけです。** 読めることは渡せることではないので、共有された側がさらに他人へ渡すことはできません。
- **何ができるか（権限グループ）と、何が見えるかは別の軸になりました。** 既定で見えるのは、`admins`はすべて、`leaders`は自分の組織のもの、`users`は自分のものです。そこへ共有された作品が足されます。
- **⚠ `leaders`に属している人は、この版へ上げた時点から自分の組織の作品が見えるようになります。** それ以外の人には、誰かが共有するまで何も変わりません。
- **系譜が持ち主をまたぐようになりました。** 読める他人の作品を親にできるので、**同じ群でも見える数は見る人によって違います**。読めない作品は中身を伏せた札として出て、`削除済み`と`非公開`を別の言葉で区別します。
- **利用者名や組織名を変えても、共有はそのまま残ります**（内部のIDで覚えているためです）。**ただしアカウントを消して同じ名前で作り直すと戻りません。**
- **`inku-cli`に`history share` / `history unshare` / `history acl` / `history peers`と、`single-user show` / `single-user set`が増えました。**

## 2026-08-10 — v2.12.0未リリース基準（Web Build 877）

版を名乗る13箇所をv2.12.0／Build 877へ更新し、**権限の決まり方が変わったことにあわせて`サーバー設定方法`§2.2・§4、`inku-cli リファレンス`、`アプリケーション導入`§7を直しました**。

- **誰が何をできるかは、roleではなく所属する権限グループが決めるようになりました。** グループは`admins`・`leaders`・`users`の3つで、増やすことはできません。
- **1人が複数のグループに属せます。** `admins`と`leaders`の両方を持つ人は、強い側の`admins`として扱われます。
- **これまでのroleは、起動時に1対1で移ります。**`admin`は`admins`へ、`group_lead`は`leaders`へ、`user`は`users`へ。**設定し直す作業はありません。**
- **`inku-cli`の旗が変わりました。**`user create --role`は受け付けなくなり、**`--permission-group {users,leaders,admins}`**を（必要なら複数回）渡します。
- **ユーザーgroup（組織のまとまり）はこれまでどおりです。** 権限グループとは別物で、1人1つのまま、権限とは独立に動きます。
- **バックアップからの復元はこれまでどおり行えます。** 利用者行の`role`列は残していて、所属から機械が書き写します。**この列を見て権限を決める場所は1つもありません。**

## 2026-08-10 — v2.11.19未リリース基準（Web Build 875）

版を名乗る13箇所をv2.11.19／Build 875へ更新し、**単独利用モードの追加にあわせて本文を直しました**。

- **配布版は、環境変数を1つも書かなくても使い始められます。** `INKU_SINGLE_USER`（配布composeの既定は`1`）を立てたサーバーは、利用者を1人に定めて自動的にログイン済みにします。**ログイン画面は現れません。**
- **`INKU_BOOTSTRAP_ADMIN_PASSWORD`の扱いが変わりました。** これまでは必須で、値が無いと`docker compose up`が起動前に停止しました。**いまはcomposeがこの値を検査しません** — 単独利用モードが on なら要らないためで、その条件をcomposeの補間では表せないからです。**`INKU_SINGLE_USER=0`にする場合は、自分でこの値を設定してください。**

- **`inku-cli`は、`login`していなくても要求を送るようになりました。** 単独利用モードのサーバーではそのまま通り、そうでないサーバーでは従来どおりの案内が出ます。
- **環境変数の一覧に`INKU_SINGLE_USER`を足しました。**（`サーバー設定`§2.2）
