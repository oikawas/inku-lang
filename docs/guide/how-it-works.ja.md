# しくみの詳細

[README.ja.md](../../README.ja.md) の「しくみ — 楽譜と演奏」の続きである。楽譜の実物、各層の用語、
パイプラインの全体、面と地の質感、プラグイン語彙をここに置く。

## 用語と層

| 語 | 対応する層・行為 |
|---|---|
| **記述** | 作者が書く詩歌的な入力。作品の最上層（inku 固有。LeWitt に対応物なし）|
| **解釈** | 記述を下絵へ読み解く Stage 1 の行為（LLM）|
| **下絵** | 解釈が返す絵の設計。どの形を、どの画材・色で、どこにどう置くかを、決まった項目に歳時記の語だけで埋める。一時的なもので、作品に残るのは指示書と楽譜 |
| **指示書（正規化DDL）** | 下絵から決定的に書き起こした実行仕様。LeWitt の指示書に相当。作者が手で書き、編集することもできる |
| **楽譜（JSON Score）** | 型付きコンパイラが指示書から書き起こす中間表現。決定的に保存される |
| **演奏（SVG）** | 楽譜を描く一回性の結果 |
| **詞書** | 記述を作品の傍らに掲げ直したもの（短歌の詞書）|
| **読み取り** | 言葉の読み直しから候補を作り直す操作（別の解釈）|

## 一枚の作品を層で追う

README のギャラリー 2 点目「魚群の銀色」を例に、各層が何を持つかを見る。この作品は Build 667 で描いたもので、当時の Stage 1 は指示書を直接書き、Stage 2 の LLM が楽譜を組んでいた。今は下絵を経て指示書が書き起こされ、楽譜は型付きコンパイラが組む。どの層が何を持つかは変わらない。記述は次の一文だった。

```
戦争が終わった朝、対岸の狙撃手と漁師は、同じ魚群の銀色を見ていた。
```

解釈がこれを指示書（正規化DDL）に読み解く。狙撃手も漁師も戦争も残らない。残るのは図形・素材・運動の語だけである。

```
背景を白で塗りつぶす。
画面下半分に灰色の細筆の横線を二十本並べる。
中央付近に白い小さな楕円を百二十個、波打つ軌跡に沿って散らす。
右端に黒い鉛筆の縦線を一本引く。
```

構造化がこの指示書を楽譜（JSON Score）に書き起こす。当時実際に保存された楽譜（Score 0.1.0）の抜粋である（3 命令のうち魚群にあたる 2 つめ、`null` の項は省いた）。

```json
{
  "version": "0.1.0",
  "canvas": "square",
  "background": "white",
  "instructions": [
    {
      "primitive": "ellipse",
      "center": [0.5, 0.5],
      "size": [0.02, 0.01],
      "rotation": 18.0,
      "filled": false,
      "weight": "pencil",
      "color": "black",
      "variation": {
        "amplitude": "medium",
        "frequency": "slow",
        "quality": "wave",
        "dimensions": ["position_x", "position_y"]
      },
      "arrangement": {
        "count": 110,
        "layout": "scatter",
        "path": "wave",
        "color_cycle": ["black", "white"],
        "density": "high",
        "cluster_count": 7,
        "fade": "outward",
        "rhythm_spacing": "loose"
      },
      "surface": {
        "texture": "wash",
        "opacity": 0.6,
        "tone_steps": 3
      }
    }
  ]
}
```

「魚群」は `count` と `cluster_count: 7` に、「波打つ軌跡に沿って」は `path: wave` に、「銀色」は `color_cycle` と `surface.texture: wash` に落ちている。「対岸」は右端の一本の縦線になった。レンダラーがこの楽譜を演奏する——毎回わずかに違う形で。出力はベクターなので、額に入れても、壁一面に引き伸ばしても、手のひらの画面で見ても成立する。物理的なサイズの制約はない。今の楽譜（0.10 以降）は、並べた個体の配置を一つずつ書かず、同じ配置を再演できる作り方（recipe）として持つ。

## パイプラインの全体

記述から SVG まで、段は次の順に進む。LLM を使うのは印を付けた段だけで、ほかはすべて決定的である。

| 段 | 何をするか | LLM |
|---|---|---|
| 写生（任意） | 記述に、場所の広がりと季節・時刻の光の補足を添える。記述は書き換えない | ● |
| 色カタログの自動選択（任意） | 記述に合う色カタログを選ぶ | ● |
| Stage 1 解釈 | 記述を下絵に読み解く | ● |
| 印字 | 下絵を指示書（正規化DDL）に書き起こす | |
| 型付きコンパイラ | 指示書を検証済みの意味にする。プラグイン語はここでコア語彙へ展開する | |
| Stage 2 補完（必要なときだけ） | 読み切れない句の補完案を出し、作者の承認を待つ | ● |
| Stage 1.5 焦点と変奏 | 「中央」に置いた要素の焦点を決まった六つの候補から選び、明示された変奏でだけ動かす | |
| 楽譜化 | 資源の上限を確かめ、楽譜（JSON Score）にする | |
| Renderer 演奏 | 楽譜を seed に従って SVG に描く。揺らぎ・領域・関係を解決する | |

写生と色カタログの選択は、失敗しても描画を止めない。指示書を直接書いて描くときは、型付きコンパイラから始まる。これらの判定は Rust の共有コアにあり、サーバーと Android アプリが同じものを使う。1件ずつの判定の道筋は [記述からSVGまで](../architecture/description-to-svg.ja.md) にある。

## 面と地の質感

楽譜には、面と地の質感も保持できる。図形の面の質（歳時記の「おもて」。塗り・薄墨・点描・平行線・交差線・アクアチントなど）は `instruction.surface`、和紙・木炭地・カンバス・メゾチントのような支持体（歳時記の「じ」）は `canvas.ground` に入る。指示書では、面の質は「薄墨の円」のように図形の修飾語として、地は「和紙。」のように一文で書く。これらは抽象属性のまま保存され、Renderer が SVG filter、clip された vector mark、compat 向けの単純化出力として演奏する。

## プラグイン語彙

コアの外には、`Nature.YoungLeaves`（日本語では別名の `Nature.若葉`）のような名前空間付きの**プラグイン語彙**がある。プラグインはコードではなく検証済みの `.inku-plugin.md` 文書で、現象を一語で呼び出してコアDDLへ決定的に展開する。新しい図形・Score項目・任意コードは持ち込まない。保存した作品は使った定義の実物を版と digest ごと持つので、プラグインを更新・削除しても同じ絵を描く。記述に対象の語があれば、下絵でも選ばれる。未登録のプラグインを含む指示書は、その文だけ理由（未登録・無効化中・名前の誤り・版違い）を示して残りを描く。作品はプラグインの定義付きで書き出し（`inku.ddl-export.v1`）、別の環境で新規DDLとして読み込める。ロード状態と拒否理由は設定画面、名前空間付き語とnoteは歳時記、管理操作は `inku-cli plugin list / validate / reload` で確認できる。
